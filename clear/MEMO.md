## 名前とデザイン

- 名前は **CLEAR**。**ARCA は数学アプリの名前なので使わない。**
- 見た目:紙(#f1f0ec)と墨の地、オーロラ(群青→菫→翠)、左下だけ大きく丸いカード、ピル型ボタン。ライト/ダークは上のバーで切り替え(初期はライト)。
- 言葉:「ランク」(「実力」は使わない)。「大会」「バドミントン大会」やキャッチコピー的な見出しは使わない。説明は短く、細かい設定は開く形にする。

## 作り直しで変えたこと(2026-11)

- **ダブルスの持ち方を全形式で1つにした。** 選手は1人ずつ(`players[]`)。ペアは2人をつなぐ記録(`pairs[] { id, a, b, level }`)。`level` はペアのランク(1〜5、自分で決める。初めは3)。**2人の平均は使わない。** 解いたペアのランクは `pairMemo` に控え、過去の回転の表示と、同じ2人の組み直しに使う。前の版の平均のペア(`level` が null)は、読み込み時にその値(四捨五入)で固定する。
- リーグ戦・トーナメントの出場単位(entry)は、シングルスなら選手、ダブルスならペア。順位・表・印刷・Excel はこの entry で同じ処理(`Core.entries`)。
- 練習試合の試合の側は選手idの配列(1人か2人)。2人のとき、表示もマッチングもペアのランクを使う(選手のシングルスのランクは使わない)。ペアにしたことがない「この回転だけのペア」だけは、組む計算で2人の平均を使い、画面にランクは出さない。
- 練習試合のペアの種類は、利用者には「固定」と「毎回組み替え」の2つだけ。以前の「登録ペア」(locked)と「固定ペア」(pairs)は1つの「ペア」にまとめた。**毎回組み替えでも、登録したペアは崩さない**(崩したいときは「解除」)。
- 自動のペア作りは**必ず同じ学校どうし**。人数が余った人は待機。違う学校のペアは、選手の画面で2人を選んで手で作る(軽い確認が出て、学校は「東高・西高」と2校出る)。
- 固定ペアの片方が休むときは、そのたびにポップアップで選ぶ:「相方も待機」か「その回転だけ別の人と組む」(相方の候補は待機中から、ランクと学校が近い順)。
- 試合カードではペアを1つのかたまりで見せる。ドラッグは、かたまりの左右のつかみ手(⠿)=ペアごと入れ替え、名前をつかむ=1人だけ入れ替え、で分けた。置き場へ落とすと「今回だけ抜く」(黄)、「次も抜く」で次の回転以降も外す(赤)。
- 名簿の貼り付けは「1行に1ペア」「1行に1人」のどちらでも読める(自動判別。取り込む前の表で見て、切り替えられる)。
- 成績は個人ごと(試合数・勝率・日ごと・出場)とペアごとの両方。見かたは「試合数と勝率」「対戦結果表」「組み合わせごとの成績」の3つ。
- 「リーグ戦 → 決勝トーナメント」は**消した**。古いデータはリーグ戦として開き、決勝の表は `legacyBracket` に残す。
- 画面から外した機能:コピーして新規作成、見本のうち2種類(今は「練習試合」「リーグ戦」の2つ)、星取表などの個別コピーボタン(Excel は「Excelにコピー」の1つ)。

## データ(v2)と移し替え

- 保存データは `v: 2`。起動時に古い形(v1)を `Core.migrate` で新しい形に移す。
- **移す前に控えを残す**:ブラウザ版は `arca-league-v1-backup`(最初の1回だけ、上書きしない)。claude.ai 版は db の `backups` コレクション(同じid、すでにあれば上書きしない)。控えは消さない。
- 移し替えの中身:ダブルスの1件は「選手2人+ペア1つ」(ペアidは旧idのまま。結果のキーが変わらない)。「東高・西高」の学校は2人それぞれの学校に分ける。10段階の時期のランクは5段階に換算。1ゲーム時代の練習試合(`m.win` など)は3ゲーム・15点に切り替え。
- 古いデータ向けの処理は `Core.migrate` に集めた。画面側にはない。

## 決めたルール(根拠つき)

- **リーグ内の順位**は BWF 一般競技規程 16.2:①勝ち数 ②2人が並んだら直接対決 ③3人以上は得失ゲーム差→得失点差(途中で2人に絞れたら直接対決) ④それでも並んだら同順位(抽選)。
- **リーグ分け**:ランク別(A が強い組)と、スネーク(どのリーグも同じ強さ)。1リーグ3〜8人。同じ学校はなるべく別のリーグへ。
- **総当たりの対戦順**は円卓方式。
- **1人1日の試合数の上限**は初期値6。超えるリーグは対戦順を「1日目/2日目」に分ける。
- **トーナメント**:2の累乗の枠。シード位置は日本の組み合わせ表の形(8枠なら A=[1,8,5,4] B=[2,7,6,3])。不戦勝は上位シードから。3位決定戦あり。シードは手で指定でき、指定した人は動かさない。同じ学校が早い回戦で当たらないよう入れ替え。
- **ランク**は 1〜5(5 が強い)。
- **点数チェック**:21点なら 21-19 以下、22〜29 は2点差、30-29 と 30-28 だけ正しい。棄権は「必要ゲーム数 × 点数 対 0」。「勝ち」ボタンは点数なしで 2-0(1ゲームなら 1-0)。
- **練習試合の組み方**の優先:①ランク差の設定 ②1つ前の回転と同じ相手にしない ③なるべく別の学校と当てる ④それ以前のかぶりを避ける(かぶった試合は表示する)。**「かぶり」は組み合わせが丸ごと同じときだけ**(`Core.matchKey`)。ダブルスは4人も組も同じ場合。1人でも違えば別の組み合わせ(表示も、避ける計算も同じ)。ダブルスで当たったのと、シングルスで当たるのは別。**練習試合の勝敗は、終わったゲームだけで数える**(`Core.gameOver`:設定の点に届いて2点差か上限)。途中の点数は「試合中」でオレンジに光る。打ち切りは「左が勝ち/右が勝ち」(点数は残る)。点数欄は外を押すと閉じ、全角入力でも2文字で次へ。**対戦の画面は日ごとのシート**(上の「1日目/2日目/＋」)。回転の番号は日ごとに1回転目から(`Core.roundNo`/`roundTitle`)。`rounds[]` は日の順に並べる(足すときは `insertAt`)。回転ごとの「日」の選択欄は廃止。番号がある回転は、抜く・入れ替えで試合の並びを変えない。名簿は、ランクを変えた瞬間には並べ替えない(`App.keepOrder`。画面を開き直すと強い順になる)。押したボタンの画面上の位置も保つ(`App.keepInPlace`)。初期のランク差は前後1。試合形式は 15点・3ゲーム(2ゲーム先取)。
- 先生から「残して」と言われているもの:1回転ごとの対戦結果表(「第◯回転・◯日目」の見出し行の下に試合が並ぶ形。勝った側を赤く「勝ち」と出す)、「試合数と勝率・出場」の表。

### 組み方の優先順位(2026-11-26)
- 練習試合の「組み方の設定」は、6つの項目のカードを上から並べる形(つかんで動かす / ▲▼ / チェックで使う・使わない)。上にあるものほど優先する。項目:前に当たった組み合わせを避ける(`fresh`) / 別の学校の人と当てる(`school`) / ランクが近い人と当てる(`level`) / 近い学年どうし(`grade`) / 同じ県どうしを避ける(`pref`) / 同じブロックどうしを避ける(`block`)。
- データ:`practice.prio`(項目を優先する順に並べた配列。なければ標準の並び fresh→school→level→grade→pref→block)。オン・オフは前からある印をそのまま使う(`avoidRepeat` / `avoidSchool` / `levelNear` / `nearGrade` / `avoidPref` / `avoidBlock`)。古いデータはそのまま動く。
- 重さ(`Core.prioWeights`):使う項目を上から数えて 250 → 50 → 10 … と5分の1ずつ。休み(2500〜5000)・ランク差の上限超え(2000/段)より、いつも軽い。
- **ランク差の上限は、先生の決まり(前後1)なので、ふつうは必ず守る**(1段超えるごとに 2000)。上限は「前後1」「前後2」から選ぶ(古いデータの 0・3 はそのまま表示)。
- 「同じ相手が続きそうなときは、ランク差の上限を超えて、違う相手に当てる」(`practice.widenTol`、標準はオフ)は、ランク5が少人数で5どうしばかり当たるときの対策。チェックを入れると、上限超えの重さが「かぶり」の0.67倍になる。ランク5が3人だけの12人・6回転のテストでは、同じ組み合わせが出た回数が、ランクだけ優先 16回 → 前と違う相手 4回 → 広げる 2回、ランク差は最大2まで広がる。
- 組むときの計算は、前より約10倍速い(64人で1回転あたり 0.15秒前後)。
