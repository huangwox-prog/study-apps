# CLEAR 引き継ぎメモ(2026-11 作り直し版)

バドミントン部の顧問向けの「練習試合・リーグ戦・トーナメント」の対戦表づくり。
別のPCや新しい Claude Code のセッションで続きをするときは、まずこのメモを読む。

## どこにあるか

| もの | 場所 |
|---|---|
| アプリ本体(1ファイル) | `clear/index.html` |
| 公開ページ(GitHub Pages) | https://huangwox-prog.github.io/study-apps/clear/ |
| claude.ai 版(持ち主だけ) | https://claude.ai/artifact/6oAYFc7wQDsfhPSrSaPSWK |
| 作り直しの部品 | `src/`(core.js 計算 / app-a.js 土台・選手・ペア / app-b.js リーグ・トーナメント / app-c.js 練習試合・成績・ドラッグ / style.css)と `build.ps1` |

- 反映の状況(2026-11-13): claude.ai 版も GitHub 版も、作り直し版に更新済み。GitHub へは、git が無いPCだったので、ブラウザの「Upload files」で `index.html`・`MEMO.md`・`build.ps1`・`確認表.md`(`clear/`)と `src/`(`clear/src/`)を上げた。
- `build.ps1 -root <フォルダ>` が `src/*` を `clear-new/index.html`(と claude.ai 用の `artifact.html`)に1ファイルにまとめる。PowerShell 5.1 は BOM なしの UTF-8 を ANSI で読むので、`build.ps1` の中は ASCII だけにする。
- `src/test.html` をブラウザで開くと、計算部のテスト(36件)が走る。タイトルが `PASS n` になれば通っている。
- GitHub 版の保存先はブラウザ(localStorage、キー `arca-league-v1`)。claude.ai 版は claude.ai の db(`events` コレクション、1件=1つ)。中身は同じ。直したら両方に反映する。
- 保存キー `arca-league-v1` / `arca-league-theme` は旧名のまま変えない(変えると今までのデータが読めなくなる)。

## 名前とデザイン

- 名前は **CLEAR**。**ARCA は数学アプリの名前なので使わない。**
- 見た目:紙(#f1f0ec)と墨の地、オーロラ(群青→菫→翠)、左下だけ大きく丸いカード、ピル型ボタン。ライト/ダークは上のバーで切り替え(初期はライト)。
- 言葉:「ランク」(「実力」は使わない)。「大会」「バドミントン大会」やキャッチコピー的な見出しは使わない。説明は短く、細かい設定は開く形にする。

## 作り直しで変えたこと(2026-11)

- **ダブルスの持ち方を全形式で1つにした。** 選手は1人ずつ(`players[]`)。ペアは2人をつなぐ記録(`pairs[] { id, a, b, level|null }`)。ランクは2人の平均が初期値(`level` が null のとき)、手で 0.5 刻みに変えられる。
- リーグ戦・トーナメントの出場単位(entry)は、シングルスなら選手、ダブルスならペア。順位・表・印刷・Excel はこの entry で同じ処理(`Core.entries`)。
- 練習試合の試合の側は選手idの配列(1人か2人)。2人のとき、登録ペアがあればそのペアのランクを使う。
- 練習試合のペアの種類は、利用者には「固定」と「毎回組み替え」の2つだけ。以前の「登録ペア」(locked)と「固定ペア」(pairs)は1つの「ペア」にまとめた。**毎回組み替えでも、登録したペアは崩さない**(崩したいときは「解除」)。
- 自動のペア作りは**必ず同じ学校どうし**。人数が余った人は待機。違う学校のペアは、選手の画面で2人を選んで手で作る(軽い確認が出て、学校は「東高・西高」と2校出る)。
- 固定ペアの片方が休むときは、そのたびにポップアップで選ぶ:「相方も待機」か「その回転だけ別の人と組む」(相方の候補は待機中から、ランクと学校が近い順)。
- 試合カードではペアを1つのかたまりで見せる。ドラッグは、かたまりの左右のつかみ手(⠿)=ペアごと入れ替え、名前をつかむ=1人だけ入れ替え、で分けた。置き場へ落とすと「今回だけ抜く」(黄)、「次も抜く」で次の回転以降も外す(赤)。
- 名簿の貼り付けは「1行に1ペア」「1行に1人」のどちらでも読める(自動判別。取り込む前の表で見て、切り替えられる)。
- 成績は個人ごと(試合数・勝率・日ごと・出場)とペアごとの両方。見かたは「試合数と勝率」「対戦結果表」「組み合わせごとの成績」の3つ。
- 「リーグ戦 → 決勝トーナメント」は**消した**。古いデータはリーグ戦として開き、決勝の表は `legacyBracket` に残す。
- 画面から外した機能:コピーして新規作成、見本のうち2種類(今は「練習試合」「リーグ戦」の2つ)、星取表などの個別コピーボタン(Excel は「Excelにコピー」の1つ)。

## データ(v2)と移し替え

- 保存データは `v: 2`。起動時に古い形(v1)を `Core.migrate` で新しい形に移す。
- **移す前に控えを残す**:ブラウザ版は `arca-league-v1-backup`(最初の1回だけ、上書きしない)。claude.ai 版は db の `backups` コレクション(同じid、すでにあれば上書きしない)。控えは消さない。
- 移し替えの中身:ダブルスの1件は「選手2人+ペア1つ」(ペアidは旧idのまま。結果のキーが変わらない)。「東高・西高」の学校は2人それぞれの学校に分ける。10段階の時期のランクは5段階に換算。1ゲーム時代の練習試合(`m.win` など)は3ゲーム・15点に切り替え。
- 古いデータ向けの処理は `Core.migrate` に集めた。画面側にはない。

## 決めたルール(根拠つき)

- **リーグ内の順位**は BWF 一般競技規程 16.2:①勝ち数 ②2人が並んだら直接対決 ③3人以上は得失ゲーム差→得失点差(途中で2人に絞れたら直接対決) ④それでも並んだら同順位(抽選)。
- **リーグ分け**:ランク別(A が強い組)と、スネーク(どのリーグも同じ強さ)。1リーグ3〜8人。同じ学校はなるべく別のリーグへ。
- **総当たりの対戦順**は円卓方式。
- **1人1日の試合数の上限**は初期値6。超えるリーグは対戦順を「1日目/2日目」に分ける。
- **トーナメント**:2の累乗の枠。シード位置は日本の組み合わせ表の形(8枠なら A=[1,8,5,4] B=[2,7,6,3])。不戦勝は上位シードから。3位決定戦あり。シードは手で指定でき、指定した人は動かさない。同じ学校が早い回戦で当たらないよう入れ替え。
- **ランク**は 1〜5(5 が強い)。
- **点数チェック**:21点なら 21-19 以下、22〜29 は2点差、30-29 と 30-28 だけ正しい。棄権は「必要ゲーム数 × 点数 対 0」。「勝ち」ボタンは点数なしで 2-0(1ゲームなら 1-0)。
- **練習試合の組み方**の優先:①ランク差の設定 ②1つ前の回転と同じ相手にしない ③なるべく別の学校と当てる ④それ以前のかぶりを避ける(かぶった試合は表示する)。初期のランク差は前後1。試合形式は 15点・3ゲーム(2ゲーム先取)。
- 先生から「残して」と言われているもの:1回転ごとの対戦結果表(「第◯回転・◯日目」の見出し行の下に試合が並ぶ形。勝った側を赤く「勝ち」と出す)、「試合数と勝率・出場」の表。

## 動かすときの注意

- claude.ai の中では `confirm()` が使えない(いつも false)ので、`App.askOk` が確認なしで進める。印刷・PDF保存もできない(公開ページで使う)。
- ドラッグは、少し(6px)動かすまでドラッグにしない。スマホの指でも動く。
- 動作確認はローカルの簡易サーバで配信してブラウザで確かめる(PowerShell の `System.Net.HttpListener` で十分)。

## 確かめていないこと(2026-11 時点)
